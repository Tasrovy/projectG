# 卡牌对战模块交接

给接手对战模块的人。范围是「一天里打开手工台、抽牌、打出、选目标、结算、结束回合」。商店买卖、Yarn 剧情正文、打工/三选一不在本文展开，只写它们和对战的接口。

主场景：`Assets/Scenes/Tasrovy.unity`（Unity 2022.3）。卡牌表在项目根目录的 xlsx，进 Play 时由 `ExcelLoader` 同步成 `Assets/Resources/` 下的 ScriptableObject。

## 1. 请原作者核对

下面几条是从当前代码和场景序列化读出来的，和设计意图可能不一致。

1. **开战按钮是测试按钮。** `Tasrovy.unity` 的 Canvas 下有一个名叫 `Button` 的物体，OnClick 调 `DUEL.Begin()`，然后把自己 `SetActive(false)`。C# 里没有任何地方调用 `Begin()`（`CardManager.Start` 里那行是注释）。`UISceneManager` 切到 `SceneType.CardFight` 只激活 `cardFightRoot`，不会抽牌，也不会打开对战 UI。

## 2. 一局怎么跑

```
玩家点 Canvas/Button
  → DUEL.Begin()
      确保 BattleDialogController 存在
      DUELUIObjectManager.ShowUI()，显示结束回合按钮
      OnBeginDUEL → InitCardObject()（按手牌生成/复用 DisplayCard）
      CardManager.DrawCard(当天 day.xlsx 的 drawNum)
          抽完再 NotifyDeckOrHandChanged → 再刷一次手牌物体

玩家点一张牌
  → CardUIObject 抬起，CardSelector 按类型改按钮文案
      1 礼物「送出」 / 2 功能「使用」 / 3 事件「邀请」
  → 点提交
      CardSelector 只抛 OnSubmitEvent
      CardActionResolver.HandleSubmit
          功能牌：记下「效果结束后放回牌堆」
          CardEffect.TakeSnapshot()          // 必须在离手之前
          HandService.BreakCard              // 从手牌移除，不触发 OnBroken
          card.OnTrigger()                   // 效果链
          若链在等玩家选牌：先返回
          否则功能牌立刻放回牌堆

效果链要选目标
  → CardEffectExecutor 把对应方法标成等待
  → CardSubmitHelper / Library 调 StartEffectSelection
  → 玩家只能点 id 万位为 1 的礼物牌
  → 确认：先 ResetToNormalMode，再执行回调（生长会在回调里再次打开选牌）
  → 取消：标记这张牌条件失败 → OnSelectCardEnd(false) → 整段回滚到快照

链正常走完
  → _onTriggerFinalize
      把这张牌的 nature1/2/3 加到 DataManager（带属性倍率）
      把 OnNextTurn 挂到「下一天」的 UnityEvent
  → 功能牌 CompletePendingPlayedCard(true) 放回牌堆

点结束回合
  → DUEL.End()：藏 UI，Destroy 手牌物体（数据还在 cardInHand / cardSet）
  → DialogueHandler.TriggerEndDayDirectly()：失败检定则播失败对话，否则过天
```

手牌和牌堆是 `Card` 的引用列表。UI 物体用引用相等来决定复用还是新建。回滚会 `new Card()` 再 `InitCard`，旧引用全部作废，所以 `InitCardObject` 会整手重刷。不要在效果链外面长期保存某张 `Card` 引用。

## 4. 数据

### 4.1 ID

五位左右的整数，按十进制位读，不按数值区间。

| 位 | 含义 |
| --- | --- |
| 万位 | 类型。1 礼物，2 功能，3 事件 |
| 千位 | 稀有度 1–3 |
| 其余 | 实例编号 |

工具：`CardIdUtility.GetCardType` / `GetCardRarity`。效果选牌的合法目标写的是 `id.ToString().StartsWith("1")`，和 `GetCardType == 1` 在正数上一致。

打出后的去向：

- 功能牌（2）：效果成功后 `AddCardToSet`，回到牌堆，同一实例。
- 礼物牌（1）、事件牌（3）：`BreakCard` 之后不回牌堆，这张实例离开手牌。`nextTurn` 仍挂在这个已经离手的实例上。
- `noConsumed()` 会再复制一张进手牌。功能牌因此会「回牌堆一张 + 手里多一张」。

### 4.2 Excel

`CardManager.cardExcelPaths` 默认：

- `giftCard.xlsx`
- `funcCard.xlsx`
- `eventCard.xlsx`

表头行必须和 `CardData` 的字段名一致（反射按列名灌）。空 id 行跳过。整数列会先按 float 再转 int，所以 `1.0` 能过。

| 字段 | 作用 |
| --- | --- |
| `id` `name` `description` `text` `prompt` | 身份、描述、详情长文、提示 id 列表 |
| `nature1` `nature2` `nature3` | 卡牌自身三项数值。0 表示这个槽不存在 |
| `sale` `sell` | 买价、卖价。提价改的是 `sell` |
| `dialog` | 大于 0 时，打出瞬间用这个 id 去 `dialog.xlsx` 显示一句 |
| `made` `broken` `added` | 见下一节，纯数字和函数字符串语义不同 |
| `trigger` | 打出时执行的函数串 |
| `nextTurn` | 打出成功后，挂到下一天开始时执行 |
| `buff` | 解析进 `buffEffects`，但全项目没有 `OnBuffUpdate()` 的调用方 |

`dialog.xlsx` 由 `BattleDialogController` 读，字段在 `DialogEntry`。立绘路径写死 `Resources/Portraits/BattlePortrait`。

`day.xlsx` 里对战实际用到的是当天的 `drawNum`。`probRarity1/2/3` 会被写进 `CardManager`，抽牌不用。

`initialHand.xlsx` 只有在场景开关打开时使用，列是 `id` 和 `num`，用来决定牌堆里每种牌有几张。表里没有的 id 打警告并跳过。

改表后要重新进 Play（Editor 下 `ExcelLoader.SyncExcelToSO`）。运行中改 ScriptableObject 不会回写 xlsx。

描述里的 `{nature1}`、`{sell}`、`{trigger}` 等由 `CardDescriptionFormatter` 替换，花括号内不区分大小写。

### 4.3 属性 0 和正负号

`CardNatureState.Add` / `AddTo`：当前值是 0 就直接返回，不会把空槽加成出数值。正数不会被加成穿过 0 变成负数，负数也不会穿过 0 变成正数，到 0 为止。

`DataManager.Add` 的 id 和卡牌属性不是同一套存储：

| id | 加到哪里 |
| --- | --- |
| 1 / 2 / 3 | 角色三项属性，乘 `(1 + currNatureXEffect)`，结果小于 0 则这次不加 |
| 4 | 金钱 `MoneyNum` |
| 5 | `extraCharm` |

卡牌自己的三项用 `Card.Add`。效果名里带 `AtSum` 的，加的是角色，不是这张牌。

## 5. 效果字符串

解析在 `CardEffectPlanParser`。多条用分号分隔：

```
addMoney(10); drawCard(1); shake(1, 0.2)
```

方法名大小写不敏感，必须是 `CardEffectLibrary` 上的实例方法。参数在 `InitCard` 时就按方法签名转好。方法名写错：`CardEffectInvoker` 直接 return，这条被跳过，链继续。参数个数不够会用默认值。

`made` / `broken` / `added` 两个写法：

| 单元格内容 | 何时执行 | 实际方法 |
| --- | --- | --- |
| 纯整数，例如 `2` | 这张牌被打出时，作为前置，排在 `trigger` 前面 | `_beMadeDirect` / `_beBrokenDirect` / `_beAddedDirect` |
| 纯整数 `0` 或空 | 不生成命令 | |
| 带括号的函数串 | 这张牌成为别人的目标时 | 原样进 `madeEffects` 等。生枝调 `OnMade`，剪枝调 `OnBroken`，生长调 `OnAdded` |

同一格里如果出现 `beMade` 或 `beBroken`，解析器会把这条插到**该格列表的最前面**。

打出时 `OnTrigger` 的顺序是：

1. `broken` 的纯数字（剪枝前置）
2. `made` 的纯数字（生枝前置）
3. `added` 的纯数字（生长前置）
4. `trigger` 列
5. 固定追加 `_onTriggerFinalize`

### 5.1 库函数

选牌类会把效果链暂停，取消则整次打出回滚。

| 写法 | 行为 |
| --- | --- |
| `beMade(n)` / `_beMadeDirect(n)` | 选 1 张礼物牌，立刻 `OnMade`。复制 n 张的事挂到**下一天**的 `GetNextDayEvent`，不是现在入手 |
| `beBroken(n)` / `_beBrokenDirect(n)` | 连续选 n 张礼物牌，每张 `OnBroken` 然后离手。手里礼物牌少于 n 时，链开始前就回滚 |
| `beAdded(num, times)` / `_beAddedDirect(num, times)` | 选 times 次，每次给选中牌的三个非 0 属性加 num，并 `OnAdded` |
| `beAddedTo(n)` | 选 1 张，三个非 0 且小于 n 的属性提到 n |
| `addNatureAtSumIf(卡牌属性id, 角色属性id, 数值)` | 选 1 张。仅当**打出者是功能牌**且目标的该属性 > 0，给角色加数值 |
| `addCardSale(n)` | 选 1 张，`sell += n` |
| `addWithSame(sameNum, trueNum, falseNum)` | 选 1 张。手里同 id 数量（含选中的这张，不含已经离手的打出者）≥ sameNum 则生长 trueNum，否则 falseNum |
| `addNature(数值, 属性id)` | 给**打出者这张牌**加属性 |
| `addNatureTo(数值, 属性id)` | 打出者该属性提到数值（受 0 和正负号限制） |
| `addNatureAtSum(数值, 角色属性id)` | 给角色加，走 `DataManager.Add` |
| `addNatureFromTo(写入的属性id, 取值的属性id)` | 角色属性：前者被赋成后者的当前值。参数顺序和名字相反，写表时按这个顺序 |
| `addNatureByOther(来源id, 目标id)` | 角色：把来源的一半加到目标 |
| `addCard(id, 数量)` | 按数据库生成新实例进手牌 |
| `addRandomCard(类型, 数量, 稀有度)` | 先从牌堆拿符合的，牌堆没有再从数据库生成。同一次调用里同一 id 不重复 |
| `addRandomCardIfNot(类型, 数量, 稀有度)` | 手里已经有该类型则什么都不做 |
| `drawCard(n)` | 从牌堆均匀随机抽 n 张进手牌，牌堆空了就停 |
| `changeHandGift()` | 毁掉手里除打出者以外的礼物牌，再随机补一张礼物牌数据 |
| `addWithSameTogether(sameNum, addNum)` | 不选牌。手里同 id 礼物牌数量 ≥ sameNum 的每一张都生长 addNum |
| `addMoney(n)` | `DataManager.Add(4, n)` |
| `addCharm(n)` | `DataManager.Add(5, n)` |
| `addCardNatureToDataManager()` | 打出者三项加到角色。`_onTriggerFinalize` 收尾时还会再调一次 |
| `noConsumed()` | 复制打出者进手牌 |
| `addAddNum(n)` | 仅当 `added` 单元格是纯数字时，改这个数字并重新解析。函数串改不了 |
| `changeProperty(ratio)` | 按 `卡牌id_ratio` 全局只登记一次。下一天把三种 `currNatureEffect` 设为 `ratio - 1`。同 id 再打出不会再生效，登记也不会清除 |
| `shake(type, extent)` / `magnify(multiple)` | 打出对话的立绘震动、缩放 |
| `triggerEventDialogue(节点名)` | 先 `DUEL.End()`，再 `DialogueHandler.TriggerEventDialogue` |

### 5.2 异步白名单

`CardEffectExecutor.ExecuteSingleEffect` 里写死了会暂停的方法名：

`addWithSame`、`beMade`、`_beMadeDirect`、`beAdded`、`_beAddedDirect`、`beAddedTo`、`addNatureAtSumIf`、`beBroken`、`_beBrokenDirect`。

新写一个要等玩家点牌的效果，必须加进这个名单，否则链不会等，后面的效果会立刻执行。

白名单里的方法如果提前 `return`（例如 `beAdded(0, 1)`，或 `addNatureAtSumIf` 打在非功能牌上），等待标记已经设上，又没有人调用 `OnSelectCardEnd`，链会停在那里。纯数字 0 在解析阶段就被丢掉，不会走到这里；函数串写 0 会。

礼物牌数量不够时，`beMade` / `beAdded` / `beBroken` 在进库函数之前就 `RollbackImmediate`，打出的牌回到快照里的手牌。

### 5.3 快照里有什么

打出提交时、`BreakCard` 之前拍一张。内容是手牌和牌堆的深拷贝，加上 `DataManager` 的三项属性、钱、`extraCharm`、三种 `currNatureEffect`。

取消选牌时 `CardSubmitHelper.RestoreCallerCard` 只做 `MarkConditionFailed`。回滚由执行器在下一次 `ExecuteNextEffect` 里做。不要再调用 `CompletePendingPlayedCard(false)`，否则会和快照各恢复一次。

快照不包含：已经挂上的 `GetNextDayEvent` 监听、`changeProperty` 的登记集合、对话 UI 状态。生枝的「下一天复制」发生在确认之后，取消走回滚，监听还没挂上。

条件失败按 `Card` 实例记在静态 `HashSet` 里，同 id 的另一张牌不会被波及。回滚后的新实例不在这个集合里。

## 6. 和日子、对话、商店的接口

`DayManager.GetNextDayEvent()` 返回 `dayNumber + 1` 的 `UnityEvent`，没有就新建。`NextDay()` 时 `Invoke` 当天的事件。监听加进去之后没有移除。生枝、`changeProperty`、`nextTurn` 都挂在这里。

`nextTurn` 只在 `_onTriggerFinalize` 且这张牌没有被标条件失败时挂上。挂的是打出时那个实例的 `OnNextTurn`。礼物牌当时已经不在手里，下一天的效果改的是这个游离实例，不会自动出现在新手牌里。

结束回合进 `TriggerEndDayDirectly`：先失败检定，通过则标记过天并跑 `EndDialogueRoutine`。失败结算 `ApplyGameFailedStateAndSwitchToBegin` 会把角色数值清零，并 `CardManager.ClearAllCards()`（手牌和牌堆都空，不会按表重建）。

商店卖牌在 `ShopTransactionService` 里直接 `cardInHand.Remove`，不走 `BreakCard` 的封装，也不触发 `OnBroken`。买牌和每日库存不在对战模块里。

`triggerEventDialogue` 会先关掉对战 UI。关的是 `DUEL.End`，不会走 `TriggerEndDayDirectly`。

## 7. UI 约定

对战界面是运行时 `Resources.Load("Prefabs/DUELUI")` 再实例化，不靠场景里摆好的那份。`DUELUIObjectManager` 用 `Transform.Find` 取节点，名字写错就空引用。现有拼写要保持：

- `SubmitButton/Submit`
- `SubmitButton/Cancel`
- `EndFlightButton`（Flight，不是 Fight）
- `CradZone`（Crad，不是 Card）
- `CardSet`、`CardSet/Num`
- `HandSet`、`HandSet/Num`
- `BattleDialog`、`BattleDialog/Portrait`、`BattleDialog/Bubble`、`BattleDialog/Bubble/Text`

手牌预制体：`Resources/Prefabs/DisplayCard`，上面同时有 `CardObject` 和 `CardUIObject`。牌堆查看器用 `Resources/Prefabs/CardInSet`。详情用 `Resources/Prefabs/CardDetailUI`。

`CardUIObject`：悬停打开详情（`ShowFixed`），按下关闭。效果选牌模式下，非礼物牌点不了。拖拽时把视觉容器挂到 Canvas 上换位，松手按兄弟顺序插回。`ArcCardLayoutManager` 在 `Update` 里每帧重排，拖拽中的牌会跳过。

`CardDetailUI` 读卡牌的 `prompt` 字段，到 `PromptItemSO` 里找对应提示。这是当前分支上新加的详情，商店和三选一的 `CardObject` 悬停也走同一个详情面板。

音效路径写死在代码里：出牌 `intangibleClick/Collect star 3`，取消 `Switch sounds/button3`，点牌 `Switch sounds/button2`，悬停 `Switch sounds/bubbleSound`，结束回合 `Switch sounds/button1`。

## 8. 常见改动

### 加一张牌

1. 在对应 xlsx 加一行，列名和 `CardData` 字段一致，id 万位对上类型。
2. `trigger` 只用第 5 节里有的函数，分号分隔，括号参数用逗号。
3. 前置消耗写成 `made`/`broken`/`added` 的纯数字；被别人生枝/剪枝/生长时才触发的，写成函数串。
4. 进 Play，看 Console 有没有 `[Card] 格式解析错误` 或 `[ExcelLoader] 转换失败`。
5. 若场景仍开着 `useInitialHandFromExcel`，新 id 还要写进 `initialHand.xlsx` 才会进牌堆。

### 加一个立即生效的效果

1. 在 `CardEffectLibrary` 加一个 public 实例方法，参数用 int / float / string。
2. 表里写 `方法名(参数)`。
3. 方法里要改手牌或牌堆时，走 `CardManager`，让它 `NotifyDeckOrHandChanged`。只改了牌面数值时再调 `DUEL.UpdateCardData()`。

### 加一个要玩家选牌的效果

1. 库方法里调 `CardActionResolver.StartEffectSelection`。确认回调的第一件事不要依赖「当前还处于 EffectSelect」：解析器会先复位再调用回调。
2. 成功路径：`CompletePendingPlayedCard(true)`，然后 `CardEffect.OnSelectCardEnd(true)`。
3. 取消路径：`CardSubmitHelper.RestoreCallerCardOnInvalidTarget()`，然后 `OnSelectCardEnd(false)`。
4. 把方法名加进 `CardEffectExecutor` 的暂停名单，否则链不等你。
5. 多次选择用递归再次 `StartEffectSelection`，和 `ShengZhang(amount, timesLeft)` 一样。不要在 Invoke 之后再 `ResetToNormalMode`，那会把下一次选牌清掉。

### 查一次「打了没反应」

Console 过滤顺序：

1. `[CardSelector][Submit]` 有没有抛出牌。
2. `[Resolver][HandleSubmit]` 的 mode 是 `NormalPlay` 还是 `EffectSelect`。
3. `[Card][OnTrigger][PlanItem]` 看实际方法顺序和参数。
4. `[Snapshot]` 是否在离手前拍过。
5. `技能发动失败` / `消耗失败` 表示礼物牌不够，已经回滚。
6. `[CardEffect] 执行效果 xxx 时出错` 是库函数抛了。方法名不存在则没有这条，只会安静跳过。

## 9. 接手时建议先确认的行为

按这个顺序在 `Tasrovy` 里点一次，比读完全部代码快：

1. 点 Canvas 上的 `Button`，确认抽出的张数等于当天 `drawNum`，手牌出现在 `CradZone`。
2. 打一张礼物牌、一张功能牌、一张事件牌。功能牌应回到牌堆计数，另外两种不应。
3. 打一张 `broken` 为纯数字、且手里礼物牌不够的牌，确认牌回到手里，角色数值不变。
4. 打一张会选牌的牌，选到一半取消，确认同样回到快照。
5. 生长一张 nature 为 0 的牌，确认那个槽仍是 0。
6. 点结束回合，确认对战 UI 关掉，并且进入过天/失败对话，而不只是把 UI 藏起来。
7. 卖一张牌，确认不会触发那张牌的 `broken` 函数串。
