# 配置、程序逻辑与三日测试指南

## 当前范围调整（2026-11-10，以本节为准）

新手操作教学暂缓制作。FlowConfigTest与FlowConfigV2的tutorial表目前都只有一行：tutorial_placeholder / 1 / tutorialPlaceholder / Dialogue / None / DialogueCompleted / 空targetId / 1。正常运行只播放占位对话，结束后进入第1天，不打开教学手工台/商店，不发放教学卡或资金。下文8步骤说明保留为后续设计参考，不是当前启用流程。

原操作教程Excel保存在ProjectHandoff/DeferredTutorials，不被流程导入器读取。后续恢复前需要重新设计并验证，不应直接把备份当作已完成教程。

手工台离场清理：动态DUELUI在公共Canvas下，不随cardFightRoot关闭而消失。现由UISceneManager在切换到非CardFight界面时统一隐藏已有DUELUI、牌堆/手牌查看器、卡牌详情，并取消当前卡牌选中；不调用DUEL.End，不结算卡牌、不推进日期，也不为清理新建UI对象。

占位版本已在PlayMode回归：占位→3天→小高潮→大高潮→Completed通过；所有候选不达标→平庸→Failed通过，两次均完成3个操作日。手工台切Talk/Shop/Select共3个离场目标验证，主面板、查看器、详情与提交/取消按钮均隐藏，清理前后日历编号不变。Console错误0。结束后退出运行，测试默认条件已恢复，测试与正式SO均同步为单条占位教程，当前选择仍为三日测试配置。未保存场景。

## 一、先运行已配好的测试

1. 停止Unity运行，执行Tools → ProjectG → 流程配置 → 使用三日测试。Console提示同步成功。此选项仅影响当前编辑器，打包时强制要求切回正式配置。
2. 正常Play，从开始/命名按钮进入。首次请求剧情自动进入教程。也可由MCP启动FlowPlaytestDriver：它仅用于测试，自动请求台词补全/下一句，并调用真实的卡牌提交和交易入口。它不能代替鼠标布局验收。
3. 看完教程占位对话后直接进入第1天，暂时不执行操作教学。
4. 每天看完剧情进入选择界面；使用现有手工台、商店或结束当天入口。第2天结束播放一段小高潮，第3天结束播放一段大高潮，再播放成功节点并返回开始。
5. 修改测试Excel后停止运行再同步/重新开局，不在运行中热改配置。
6. 正式内容就绪后执行Tools → ProjectG → 流程配置 → 使用正式配置。测试表位于Resources/FlowConfigTest；正式表仍在Resources/FlowConfigV2；原Resources/day.xlsx未修改。不要把测试表复制覆盖正式表。

三日模式为了快速检验把间隔缩短；正式配置仍可第3、5天小高潮，第8天大高潮。测试日历用2026年6月15～17日，均为工作日。testDay01.yarn文件内部实际节点名为testDay；Excel填testDay，不是testDay01，也不带.yarn。已有day9_9.yarn副本内部另有testDay01，测试表不引用它。

## 三、正式配表的顺序

先写Yarn并确认编译成功 → story定义剧情 → checkpoint列出每次候选 → stage列出检查点 → tutorial配置教学 → day安排每日剧情 → 同步SO → 开局验证。

### story：每行一段剧情

|表头|作用与例子|
|---|---|
|storyId|唯一稳定ID，如coffee_01；图鉴键，发布后不要随意改|
|displayName|策划名称，如咖啡馆邀约|
|entryNode|Yarn内部title对应名称，如coffee_start|
|conditionLua|如return stats.nature1 >= 30；空按true，必须返回布尔|
|enabled|Excel布尔TRUE/FALSE；禁用候选不会被选择|
|notes|备注，不执行|

storyId不是Yarn节点名，两者通过entryNode连接。多节点的完整剧情只填入口节点；内部可jump到其他节点，整条链真正结束后才记录观看并推进流程。禁止为了过天从剧情主动跳到另一天校园剧情，应让流程控制器负责。

### checkpoint：每行一次检查

|表头|作用与例子|
|---|---|
|checkpointId|唯一ID，如s1_cp_03|
|stageDay|阶段内第几个正式操作日结束时判断，例如3|
|checkpointType|Minor或Major|
|storyIds|候选storyId，用英文分号隔开，如coffee_01;walk_01;library_01|
|fallbackStoryId|Minor无合格剧情时的兜底storyId，启用且conditionLua为return true；Major空|
|failureNode|Major无合格剧情时的Yarn失败入口；Minor空。这里直接填节点，不填storyId|

第3天候选1/2/3、第5天候选4/5/6应分成两行，列表互相独立。不需要手填候选数量。允许跨检查点有意复用某个剧情ID；图鉴记录也共享。

### stage：每行一个大高潮阶段

|表头|作用与例子|
|---|---|
|stageId|阶段ID，如stage_01|
|checkpointIds|如cp03;cp05;cp08，只存检查点ID|
|nextStageId|大高潮通过后的下一阶段；末阶段空|
|successNode|末阶段通过后的成功Yarn入口，非末阶段可空|

首行是首阶段；列表按stageDay递增，同日不重复，末项必须Major，之前为Minor。新阶段的stageDay重置为1，但日历继续前进。大小高潮都在检查点表，阶段表不重复存日期或候选。

### day：每天的资源与校园剧情

正式模式继续读取旧Resources/day.xlsx，并保留所有旧表头。dailyDialog填写该日Yarn入口，现已改为当天玩家操作之前播放；drawNum/profit/getCardNum/概率/skipBackground仍保留。旧specialDialog、failedDialog、target1/2/3/4/targetCharm在新流程不参与判定，不需要删除。

dayNumber是现有日历行号，周末会自动跳过；stageDay才是正式玩过的操作日计数。不要把两者混用。整个游戏所需工作日必须足够覆盖所有阶段，否则报配置不足而不是玩家失败。

测试day.xlsx是隔离副本，字段与DayData一致，含day/date/dailyDialog和资源列。导入器将其嵌入测试FlowConfig.asset，在测试开局临时替换DayManager.daySO，不修改旧day文件。正式模式仍使用旧day资产。

## 四、新手教程如何配置

|表头|作用|
|---|---|
|stepId|唯一步骤ID|
|order|正整数顺序，不重复|
|entryNode|步骤开始时的Yarn提示；纯剧情步骤必须填有效入口|
|uiMode|Dialogue、Craft、Shop，分别映射Talk、CardFight、Shop界面|
|allowedAction|None、PlayCard、Combine、Dismantle、Attach、Buy、Sell、Free|
|completionEvent|等待的成功事件，见下表|
|targetId|指定卡牌/商品ID；空匹配任意；不是Yarn名|
|requiredCount|成功次数，通常1；新步骤清零|
|notes|策划备注|

|步骤|uiMode|allowedAction|completionEvent|
|---|---|---|---|
|开场|Dialogue|None|DialogueCompleted|
|出牌|Craft|PlayCard|CardPlayed|
|生枝|Craft|Combine|CardCombined|
|剪枝|Craft|Dismantle|CardDismantled|
|生长|Craft|Attach|CardAttached|
|购买|Shop|Buy|ItemBought|
|出售|Shop|Sell|CardSold|
|结束提示|Dialogue|None|DialogueCompleted|

操作步骤先完整播放提示，再打开对应UI等待操作；看完提示不等于完成操作。纯剧情步骤requiredCount应设1，targetId留空。操作targetId通常留空，确实需要指定卡才填写真实数字ID；当前自动教学资源以礼物卡作为目标。

Combine等名称沿用配表枚举，对应现有生枝复制、剪枝和生长，而不是另开发一种多卡合成。生枝按模板礼物ID上报（复制结果ID相同）。程序按操作类型从卡库选择made/broken/added正整数的操作卡并临时发放材料；购买补资金，出售补礼物手牌。若卡库没有适用卡会报配置错误。教学资源结束后恢复开局资源，教学属性不带入正式局，教学不消耗stageDay。

可以增删步骤或只留开场步骤来快速测日循环；不要用伪造完成事件绕过正式教程。更多教程动作需要同时增加枚举校验、允许操作判断、成功事件和资源准备逻辑。

## 五、Lua条件与抽选

stats.nature1友情羁绊，nature2情绪依赖，nature3安全感，money金钱，charm按当前权重计算的魅力。progress.stageId/stageDay提供阶段信息。seen(id)查询跨局图鉴；seenThisRun(id)查询本轮已经完成的剧情；flag(key)查询标记。Yarn用<<flow_flag "test_coffee" true>>设置本轮标记，未设置默认false。

```lua
return stats.nature1 >= 30 and (stats.nature2 >= 10 or stats.nature3 >= 20)
```

```lua
return seenThisRun("coffee_01") and not flag("relationship_broken")
```

不要把seen(id)当作本轮发生过；跨局图鉴不代表这周目有前置剧情。使用and/or/not与~=，不要写&&/||/!。条件执行环境独立，只读快照，不提供文件/系统接口，10000指令预算；非布尔、语法错误和运行异常是配置错误。

抽选顺序：当前storyIds → 启用且Lua通过 → 有未看只抽未看 → 全部看过抽全部合格 → 空则Minor兜底/Major失败。兜底不依赖未看；小高潮从来不会因为“全看过”而变成平庸剧情。

## 六、程序实现路径

1. FlowConfigImporter反射匹配表头与FlowStage/Checkpoint/Story/Tutorial字段，只读第一张表。校验引用、顺序和Lua语法后写SO；构建只允许正式配置。FlowConfigLocation控制编辑器配置选择。
2. GameFlowController是独立常驻对象，避免Talk根节点关闭导致协程中断。首次StartDialogue接管开局，BeginRun加载配置、验证Yarn节点、保存开局资源，然后执行教程。
3. 教程状态TutorialPrompt→TutorialAction，成功事件匹配targetId并计数，再进入下一步。ShopTransactionService成功交易后通知；卡牌效果先缓存在transactionEvents，效果链成功提交，回滚丢弃。
4. 教程完成后StartMorning播放day.dailyDialog，完成进入PlayerAction。结束当天调用FinishDay，阶段日查检查点；一次性读取数值快照评估全部候选，用StorySelection决定优先未看的随机集合。
5. 播放剧情时保存回调；DialogueHandler检测整条Yarn运行结束，等待奖励结算、清理演出，再回调流程控制器。Minor完成后过天；Major成功换阶段或成功结束，失败剧情结束后失败返回Begin。
6. DaysUntilCheckpoint驱动新目标UI，不再展示旧随机单属性目标；DUEL抽牌使用CurrentDayData修正下标；次日事件按实际下个工作日注册。

运行中选择结果和阶段进度仅保存在内存，尚无完整中途存读档；图鉴写PlayerPrefs的Flow.Seen.storyId，结果写Flow.LastResult。自动化输入测试不等于验证所有按钮布局或长剧情。不要将本指南中的测试成功条件当作正式数值平衡。

## 七、分支复测方法

2026-11-10实测：真实教程操作及3天主链路到达Completed；将测试候选条件临时全部置false后，观察到testFallback并在第3天到达Failed。测试还发现并修复：教学资源误选附带80张礼物消耗的大盲盒（改为优先低消耗功能卡）；CardChoosing在最后一天使用dayNumber而非dayNumber-1越界（改用CurrentDayData）。完整鼠标按钮布局仍需人工验收，自动化使用实际提交/交易入口但没有逐个点击所有界面按钮。

修复后再次跑完整教程和3天链路，结果Completed，Console错误0。测试结束已退出Play Mode，恢复测试默认条件并保留三日测试配置选择，方便直接Play复测。没有保存场景。运行中原有ExcelLoader会自动同步其旧SO缓存，TMP动态字体也可能新增测试文字字形；旧Excel文件没有改写。

- 正常成功：测试条件均>=0，常规非负属性下可小高潮并成功通关。
- 平庸：把三段小高潮conditionLua均改为return false，同步重开；第2天应testFallback。
- 大高潮失败：把两段大高潮conditionLua均改为return false，同步重开；第3天应testFailure，不能成功。
- 优先未看：重复开局比较小高潮；有未看时只在未看集合中抽，全看后允许重复。
- 实际前置：某候选用return seenThisRun("test_minor_1")，只在本轮播过小高潮1后通过。
- 配置报错：填错entryNode，应暂停ConfigError而不是判负。

恢复测试默认时用return stats.nature1 >= 0等原条件；正式图鉴不要全局清空PlayerPrefs。只需重测图鉴时仅删除Flow.Seen.test_*测试键。
